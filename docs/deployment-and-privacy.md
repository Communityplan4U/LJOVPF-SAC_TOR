# Deployment and privacy

Deploy this code as a new GitHub repository and separate Vercel project. The production frontend keeps gateway tokens server-side in Vercel functions. The Supabase service-role key stays in Supabase and is never configured in Vercel. Use an isolated Supabase project in Canada Central and apply the dedicated SAC setup script `supabase/schema.sql` to the new project through its SQL Editor. Do not add access policies for anon/authenticated. Deploy the restricted `supabase/functions/survey-storage/index.ts` Edge Function and set `supabase/config.toml` to disable platform JWT verification only for this function; the function instead authenticates independent 64-character-or-longer gateway tokens against SHA-256 digests stored in Supabase secrets. Give ordinary Vercel routes only `SURVEY_GATEWAY_TOKEN`, and the administrator export route its separate `SURVEY_GATEWAY_ADMIN_TOKEN`. Test RLS and unauthorized gateway access before launch. Replace the assessment JSON only with the authorized 12-component review. Enable Resend email only after verifying the sender domain and configuring a dedicated environment variable.

Review privacy notice, deletion, retention and anti-bot protections before accepting submissions from the public. Results link contains a secret bearer token; do not send it to third parties. This repository includes a private administrator CSV export; limit the export secret to authorized team members.
